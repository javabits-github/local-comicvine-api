- [x] **UPD-4 — Issue/volume relationships can be invalid when the volume is absent.** Done: the endpoints already run in the correct order (volumes before issues — see `runSync`), but each endpoint uses its own independent date window from its own `last_sync_date`, and a failed volume sync does not stop the issue sync. Two cases can leave an issue pointing at a volume that has no local row: (1) the volume sync exhausts its rate-limit retries and returns before upserting, while the issue sync later in the same run succeeds; (2) a newly-updated issue in the issue window references a volume whose update window the volume sync didn't cover and which has no prior row. If the volume cannot be fetched (rate-limit exhaustion / bad reference), the issue is skipped gracefully (no stats increment, no resume-state or metadata advance) rather than aborting the whole issue sync. `upsertVolume` and `upsertIssue` are extracted as reusable methods (the volume sync loop also uses `upsertVolume` with an identical SQL body). See UPD-6 for the FK diagnostics that surfaced these failures.
- [x] **UPD-6 — Diagnose FK failures during issue sync.** During `npm sync`, upserts of issues whose `volume_id` references a `cv_volume` row absent from the local subset throw `FOREIGN KEY constraint failed`, and the endpoint's catch logged only a bare "Skipping metadata update for issues" with no way to identify which FK / row / SQL failed. Fixed in [src/updater.js](src/updater.js): the pre-existing `runWithFkDiagnostics` method was broken in two ways — (1) it iterated `fk` without ever querying `PRAGMA foreign_key_list(table)`, and (2) the issue upsert SQL was passed to an orphaned `prepare()` call that never assigned `issueSql`, so every issue upsert threw `ReferenceError: issueSql is not defined` before reaching the FK check. Both are fixed: `runWithFkDiagnostics` now queries the table's FK list (with a try/catch guard), resolves the offending value by mapping the FK column to its `?` position, checks whether the referenced row exists locally, and records a `sync_errors` row before rethrowing. The issue upsert SQL is now a real `const issueSql` template. Note: the *root cause* of the FK failures (dangling issue→volume refs) is still open as UPD-4; this item only adds the diagnostics to identify them.
